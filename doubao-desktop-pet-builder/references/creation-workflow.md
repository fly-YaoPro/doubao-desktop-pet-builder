# 创建工作流

## 首轮只确认会改变路线的信息

确认输入类型、视觉方向、角色身份/性格、目标平台。技术细节写默认值，不让普通用户先填配置表。

- 单张图片：默认适度卡通化，可改为保留原貌或只提取标志元素。
- 完整动作素材：检查后复用，只有缺失、不可达或不合格的动作才补。
- 纯文字：先用 `image_gen` 创建唯一 `core-ip`，确认后转 `image_edit`。
- 已有 Electron 工程：进入修复模式，不无故推倒重做。

## 六轮渐进共创

1. **角色轮**：提炼物种/类别、名字、性格、标志特征和目标平台。
2. **体验轮**：给出 2–4 个与角色匹配的首版互动及理由。用户没意见时采用推荐组合，不机械追问。
3. **母版轮**：创建/标准化 `core-ip`，确认身份、比例、材质和配色。
4. **动作轮**：只生成首版功能会使用的多帧动作。每个可见动作先画 5 个关键阶段，幅度大时补到 6 帧；按状态成组生成并展示“动作 × 帧 × 入口 × 对齐指标”联系表。
5. **试玩轮**：搭建工程、自动检查，运行 `npm run dev`。等待模板输出 `DEV_PREVIEW_READY` 后，明确告诉用户“这是开发预览，不是最终版，尚未打包”，再让用户实际体验角色大小、动画节奏、菜单、提醒和面板。
6. **扩展交付轮**：根据角色提出少量附加功能，用户选择后迭代；体验确认后才跑 E2E、目标平台构建和真人清单。

## 首版功能基线

默认开启透明窗口、拖拽、托盘、贴边、提醒、角色化互动、关系数据和面板。文件口袋、全局打字、自动行走默认作为试玩后的建议项；用户明确需要时提前开启。

基础版至少具备：

- 待机呼吸与自然眨眼；
- 2–4 个角色专属互动，有动作、文案和数据反馈；
- 右键/交互入口；
- 快捷提醒和到点反馈；
- 圆润的控制面板，显示名字、好感度、心情、互动次数或陪伴时长中的至少三项；
- 拖拽和贴边反馈。

## 试玩后的建议方式

不要笼统问“还要加什么”。根据角色和当前缺口给 2–4 个具体建议，例如：

- 猫：逗猫棒、踩键盘、追尾巴、舔毛；
- 狗：接球、摇尾巴、叼拖鞋、守门；
- 兔子：吃胡萝卜、竖耳、蹦跳、钻纸箱；
- 拟人物或物品：从身份、职业、材质和用户用途推导，不硬套宠物动作。

每个建议写清新增入口、动作素材、数据变化和预计影响；用户未选择的不要生成。

开发预览就绪后主动给建议，不要等用户自己想功能。只推荐当前尚未实现的 2–4 项，并先提示用户完成一次互动和一次提醒；试玩反馈处理完再进入可执行版构建。

## 返工方向

- 身份漂移：回到 `core-ip` 或用 `image_edit` 修动作，禁止独立文生图。
- 动态弱：先补关键姿势和过渡帧，再调帧速；程序呼吸只做微动，不能替代动作帧。
- UI 像系统窗口：重做无边框容器、色板、圆角、层级和角色文案，不靠堆表情符号遮丑。
- UI 出现底色框/滚动条：先修复透明宿主、`html/body` 溢出和原生控件外观，再谈配色；不得把系统滚动条藏在截图范围外冒充修好。
- 桌宠过大：同时检查窗口默认档位和透明画布的主体占比；不要只把下拉框改名。
- 素材未使用：删除无入口状态，或先实现并测试对应触发；不能留着当“以后可能用”。
- 自动测试失败：保存日志定位修复，不用“本地应该没问题”代替证据。
- 素材空白：先核对 spec 路径、实际文件、大小写、Webpack 递归导入和图片 `naturalWidth`；不要先猜窗口太小或躲在角落。
- 中文乱码：回到 UTF-8 源 spec 重建，禁止用 PowerShell 默认编码覆盖 JSON、HTML 或 `package.json`。
