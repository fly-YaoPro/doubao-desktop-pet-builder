# 修复与打包工作流

## 修复模式

1. 先运行只读审计：`python scripts/audit_project.py <工程目录> --json <报告>`。
2. 创建独立修复副本，复制源码和锁文件，排除 `node_modules`、`.webpack`、`out`、`release`、日志与缓存。若用户明确要求原地修改，再备份关键配置并在报告中注明。
3. 把发现分成：阻断启动、安全边界、功能错误、跨平台、资产质量、测试缺失。优先修阻断和安全问题。
4. 尽量局部修复；只有架构无法满足独立窗口、preload 边界或跨平台存储时才迁移到模板。
5. 每个“已修复”必须对应自动检查、复现步骤或截图/日志证据。无法在当前系统复现时写“待在目标系统确认”。

重点检查：

- `nodeIntegration`、`contextIsolation`、sandbox、CSP、`innerHTML` 注入；
- renderer 直接文件访问、完整 `ipcRenderer` 暴露、IPC 未校验 sender/payload；
- 不存在的 Electron API、变量初始化顺序、重复 `app.whenReady()`；
- 硬编码盘符、仅主屏定位、物理像素/DIP 混算；
- 提醒数据结构是否前后一致，退出/重启是否恢复；
- 全局键盘监听是否只发活动脉冲并在退出时释放；
- 未捕获异常是否被吞掉；
- 透明度、锚点、缺帧和镜像许可。

## 单独打包模式

1. 确认工程能启动、依赖锁文件存在、应用 ID/版本/图标/产物名明确。
2. 运行项目已有测试；没有测试时至少运行模板审计、类型检查、资产 QA 和启动冒烟。
3. Windows x64 在 Windows 上构建；macOS 当前架构在真实 Mac 上构建。不要把跨平台下载依赖等同于真实产物验证。
4. 将安装包复制到 `release/`，生成 SHA-256 清单。
5. 实际安装/解压后走真人短清单。未签名警告是交付风险，不是构建失败，但必须明确提示。

## 报告最小字段

- 模式、源工程、修复副本或生成目录；
- 已验证平台/架构与未验证平台；
- 自动测试命令、退出码、日志和截图路径；
- 真人验收逐项结果；
- 产物、大小、SHA-256；
- 未签名提示、剩余风险与“待确认”项。
