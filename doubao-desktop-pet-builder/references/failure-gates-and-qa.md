# 失败门禁与验收

这些门禁来自真实桌宠项目和两段完整共创记录的反向复盘。命中任一阻断项时，不得宣称完成。

## 禁止换路掩盖问题

- 不要在核心形象未确认前开始大规模写代码或生成全部动作。
- 不要因一个动作失败就更换整套技术路线；先判断是提示词、素材、抠图、状态机还是平台问题。
- 不要调用不存在的 Electron API，不要凭记忆猜运行时能力。
- 不要把重新生图当成透明度、裁切、锚点、文件命名等确定性问题的修复方式。
- 不要反复声称“已修复”但不给复现和测试证据。

## 视觉阻断项

- 动作与 `core-ip` 的身份、配色、比例或配饰明显漂移；
- 模型伪透明、白底当透明、全局近白阈值误删主体；
- 主体触边、背景与主体冲突、明显色边、缺帧或锚点漂移；
- 未许可镜像、空闲状态身体朝向反复翻转；
- 用整图旋转冒充局部动作。

## 工程阻断项

- renderer 开启 Node、直接访问文件系统或接收完整 IPC 能力；
- 面板/提醒被挤进桌宠透明小窗导致裁切；
- 拖拽在多屏或缩放下跳变，使用猜测的缩放系数或魔法位置常量；
- 多套状态定时器互相覆盖，没有抢占、恢复和销毁规则；
- 全局键盘监听记录键值、误触发、权限失败导致主程序崩溃，或退出时未释放；
- 硬编码 Windows 盘符或假设 `File.path` 永远可用；
- 全局吞掉未捕获异常、窗口丢失仍报告“持续运行”。

## 自动检查

必须保存命令、时间、退出码和证据路径：

1. `validate_pet_spec.py`：schema、12 核心状态、路径策略、未签名边界。
2. 单元测试：状态抢占/恢复、计时器清理、点击拖拽阈值、提醒持久化、文件重名、跨平台路径、打字模块降级。
3. `qa:assets`：尺寸、alpha、边缘、触边、锚点、缺帧、联系表。
4. Playwright Electron：窗口数量、控制台/页面错误、提醒窗、面板、IPC、关键截图。它只提供自动证据，不替代真人验收。
5. 目标平台构建和清单校验。

## 真人短清单

Windows 与 Mac 分别执行：启动/退出、托盘、左右键、点击/拖拽阈值、多屏与 DPI、置顶、贴边/探头、提醒、面板、文件拖入与重名、打字权限拒绝、重启恢复、安装包运行。

两端各至少一次 60 分钟稳定性测试：无未处理异常、窗口丢失、监听器泄漏、持续增长的计时器或内存明显单向增长。无法在当前系统完成的端明确写“待确认”。

GUI 验收固定使用“自动检查 + Windows/Mac 真人验收”，不使用 `computer-use`。

## 豆包安装后的三组前向测试

1. 普通用户五轮共创：上传一张图片，完成母版确认、联系表和桌宠交付。
2. 专家直出回归：导入已有桌宠，诊断并修复，不无故推倒重做。
3. 打包回归：分别在真实 Windows/Mac 生成对应产物。

展开每轮豆包思考记录，检查是否方案反复换路、调用不存在 API、无证据声称修好、独立文生图破坏一致性、用生图代替确定性修复。实际观察与预先写好的期望真值分开记录，避免事后迁就结果。
